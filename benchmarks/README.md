# 两种作用域实现的性能比较

- `src/scope1.cpp`：作用域栈，每层维护 `unordered_map<string, Variable>`，查找从内向外逐层进行。
- `src/scope2.cpp`：`unordered_map<string, vector<Binding>>`，一个名字对应一个绑定栈，查找直接取栈顶。

新版本中，每个绑定同时记录声明深度；同名栈顶的深度等于当前深度时，拒绝重复声明。每层另有一个成功声明的名字列表，`Dedent` 只弹出列表中名字的绑定，空栈从哈希表删除。这样内层遮蔽结束后能恢复外层值，修改未被遮蔽的外层变量也会保留。非法声明不会写入绑定栈或名字列表。

为了比较数据结构的影响，原版本保持原样，新版本沿用原版本的分词、参数校验、值表示、运算和输出逻辑。这次改动没有修复原有整数解析逻辑（例如 `INT_MIN` / `INT_MAX` 被严格不等式排除）；通过公开数据不代表所有非法输入和整数边界都已覆盖。

## 复杂度

设 `d` 为当前作用域深度，`k` 为退出层声明的变量数，`V` 为当前仍存活的绑定总数；下表忽略字符串长度，哈希操作使用平均复杂度，向量插入使用均摊复杂度。

| 操作 | 作用域栈版本 | 名字绑定栈版本 |
|---|---|---|
| 查找可见变量 | O(d)，内层命中时 O(1) | O(1) |
| 检查本层重复声明 | O(1) | O(1) |
| 声明变量 | O(1) | O(1) |
| 进入作用域 | O(1) | O(1) |
| 退出作用域 | O(k)，销毁本层哈希表 | O(k)，逐个回滚绑定 |
| 存储空间 | O(V + d) | O(V + d)，名字列表和绑定向量带来额外常数开销 |

## 实测结果

2026-10-11，Intel Core i7-14650HX，WSL2 Linux x86_64，GCC 13.3.0，统一使用 `-std=c++17 -O2`。每个场景重复 7 次，交替运行两版，报告中位数。时间是完整程序的墙钟时间，包含启动、解析、执行、输出及 `/usr/bin/time` 启动开销；输入来自文件，输出重定向至 `/dev/null`。内存是 `/usr/bin/time` 记录的单次进程峰值 RSS 的中位数，不包含 Python 测试驱动和编译器。

| 场景 | 指令数 | scope1 时间/ms | scope2 时间/ms | 加速比 scope1/scope2 | scope1 峰值/MiB | scope2 峰值/MiB |
|---|---:|---:|---:|---:|---:|---:|
| 公开最大混合数据 | 999999 | 425.04 | 354.47 | 1.20x | 7.12 | 8.44 |
| 浅层访问 | 999999 | 155.33 | 159.94 | 0.97x | 3.56 | 3.56 |
| 深层访问全局变量 | 999999 | 624.55 | 169.61 | 3.68x | 3.56 | 3.56 |
| 深层直接访问遮蔽变量 | 999999 | 162.47 | 168.03 | 0.97x | 3.56 | 3.56 |
| 深层查找不存在的名字 | 999999 | 660.50 | 201.35 | 3.28x | 3.56 | 3.56 |
| 大量不同名字的声明 | 999999 | 904.24 | 1327.32 | 0.68x | 136.33 | 212.61 |
| 反复声明并退出同级作用域 | 999921 | 386.34 | 441.78 | 0.87x | 5.25 | 5.86 |

深层场景使用 99 次 `Indent`，全局作用域加上嵌套作用域共 100 层，符合题目约束。深层外部变量和查找失败场景的每层还声明一个不同名字，保证原版本需要查询非空哈希表。正常访问交替执行 `Add`、`SelfAdd`，只加零以避免溢出；遮蔽场景每层重复声明 `x/y/z`，使原版本也能在最内层直接命中。大量声明场景在全局声明 999998 个不同名字；反复退出场景使用 80 个同级作用域，各层复用相同的名字。具体输入生成方式见测试脚本。

名字绑定栈主要适合频繁访问外层变量的深层程序，在公开最大混合数据上本次快约 20%。浅层访问或内层命中时，原版本本来就只查一张哈希表，新版本没有明显收益。大量声明不同名字时，新版本需要维护每个名字的向量并额外保存回滚名字，实际耗时增加约 47%，峰值内存增加约 56%。所以两种实现各有适用场景，不能只凭查找复杂度判断总体性能。小差异会受到系统负载、分配器和运行顺序影响，结果应以目标机器复测为准。

## 复现和验证

在仓库根目录运行（需要 Python 3、GCC 和 GNU `/usr/bin/time`）：

```sh
python3 scripts/compare_scope.py --csv benchmarks/scope_comparison.csv
```

脚本在临时目录编译两版并生成输入，不覆盖原有可执行文件；先检查两版在全部 10 组公开数据上的输出是否符合 `.out`，再检查跨类型遮蔽、同层重复声明、外层变量修改、别名运算、非法操作不改变状态、同级作用域重用名字和全局退出等回归场景；计时前比较每个性能场景的完整输出。原始 98 次测量记录在 `scope_comparison.csv` 中。

可以用 `--repeats 3 --commands 100000` 缩短合成数据测试，公开最大数据始终保持原大小。新版本还在全部 10 组公开数据上通过了 AddressSanitizer 和 UndefinedBehaviorSanitizer 检查：

```sh
g++ -std=c++17 -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer src/scope2.cpp -o /tmp/scope2-sanitized
```

新版本单独编译使用：

```sh
g++ -std=c++17 -O2 src/scope2.cpp -o /tmp/scope2
/tmp/scope2 < data/public01_example.in
```
